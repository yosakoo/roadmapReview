# Ревью Hangman

Проект: https://github.com/themidnightdev404/hangman

[Ревью сделано в рамках учебной подписки](https://zhukovsd.it/services/student-subscription/)

<img src="https://i.pinimg.com/736x/ed/5e/61/ed5e611702822956a6c5718cae731a01.jpg" width="400"/>

Код разбит по файлам (`main.go`, `game.go`, `ui.go`, `words.go`), состояние игры лежит в типе `Game` с методами. Структура зрелая, игра запускается и работает. Есть один баг, который ломает запуск на Linux и macOS, и несколько мелочей.

---

## ХОРОШО

- **Есть тип `Game` с методами** (`Guess`, `IsWin`, `IsLose`). Состояние собрано в одном месте, а не размазано по локальным переменным.
- Файлы разделены по смыслу: меню в `main.go`, логика в `game.go`, ввод-вывод в `ui.go`, загрузка слов в `words.go`.
- Ввод проверяется через `unicode.Is(unicode.Cyrillic, char)`. Латиница и другие алфавиты отсекаются, в отличие от `unicode.IsLetter`, который пропускает любую букву.
- Есть проверка на ровно одну букву.
- Повтор буквы заблокирован через `UsedLetter`, использованные буквы видны игроку.
- Слова читаются из файла, пустые строки отфильтрованы при загрузке.
- Слова в `words.txt` и ввод приводятся к нижнему регистру, рассинхрона по регистру нет.
- `rand.Intn(len(words))` даёт корректный диапазон, off-by-one нет. `rand.Seed` не вызывается, и правильно: Go сам инициализирует генератор.
- `STAGES` объявлен на уровне пакета и не пересоздаётся каждый ход. `maxMistakes` вынесен в константу.
- При проигрыше показывается финальное состояние: полный висельник, маска и правильное слово.

## ЗАМЕЧАНИЯ

### 1. Файл открывается как `Words.txt`, а называется `words.txt`

```go
file, err := os.Open("Words.txt")
```

Файл в репозитории называется `words.txt`, с маленькой буквы. На Windows это проходит, потому что файловая система регистронезависимая. На Linux и macOS `os.Open("Words.txt")` файл не найдёт, выведет "Ошибка открытия файла" и вызовет `os.Exit(1)`. В README написано просто `go run .`, без оговорок про ОС, так что на не-Windows игра не запустится.

Имя в коде должно совпадать с именем файла:

```go
file, err := os.Open("words.txt")
```

### 2. Смешаны `fmt.Scan` и `bufio.NewReader` на одном stdin

`fmt.Scan` читает токен, но оставляет перевод строки в буфере. Чтобы его убрать, стоят парные вызовы:

```go
bufio.NewReader(os.Stdin).ReadBytes('\n')
bufio.NewReader(os.Stdin).ReadBytes('\n')
```

Здесь два момента. Каждый вызов создаёт новый `bufio.Reader`, а он читает с запасом во внутренний буфер. При создании следующего ридера всё, что он прочитал сверх нужного, пропадает. Работает это только потому, что в терминале ввод приходит построчно. И двойной `ReadBytes` подогнан под остаток от `fmt.Scan`.

Лучше завести один `bufio.Reader` на всю программу и читать им строки, не мешая с `fmt.Scan`.

### 3. Любой ввод кроме "1" выходит из игры

```go
if game == "1" {
    // ...
} else {
    fmt.Println("Выходим")
    os.Exit(0)
}
```

В меню две опции: "1 - Новая игра" и "2 - Выйти". Но в `else` попадает не только "2", а вообще всё. Ввёл "3" или промахнулся по клавише, и программа закрылась. "2" стоит обрабатывать как выход явно, а на остальное писать про неизвестную команду и показывать меню заново.

### 4. Переменная `game` хранит не игру, а пункт меню

```go
var game string
// ...
fmt.Scan(&game)
if game == "1" {
```

В `game` лежит выбор в меню ("1" или "2"), а не игра. Имя сбивает с толку. Понятнее `choice` или `menuInput`.

### 5. Состояние дублируется: `Guessed` и `UsedLetter`

```go
type Game struct {
    Word       string
    Mistakes   int
    Guessed    []string
    UsedLetter map[rune]bool
}
```

`Guessed` хранит угаданные буквы, `UsedLetter` все введённые. Часть данных повторяется, и буква оказывается то в слайсе строк, то в map рун. Достаточно одного `map[rune]bool` со всеми введёнными буквами, а угадана буква или нет проверять по слову. Тогда не нужно держать две структуры в синхроне.

### 6. `guessedStr` собирается заново внутри цикла

```go
func (g *Game) IsWin() bool {
    for _, letter := range g.Word {
        guessedStr := strings.Join(g.Guessed, "")  // склейка на каждой букве
        if !strings.Contains(guessedStr, string(letter)) {
            return false
        }
    }
    return true
}
```

`strings.Join` стоит внутри цикла и пересобирает строку на каждую букву слова. То же самое в `printWordState`. Достаточно собрать строку один раз до цикла.

### 7. Проверка буквы через `strings.Contains`

`Guess`, `IsWin` и `printWordState` ищут букву через `strings.Contains`. Для одиночных букв это работает, но `Contains` ищет подстроку, а не отвечает на вопрос "есть такая буква". По смыслу это `map[rune]bool` (см. п. 5): наличие буквы это про множество, а не про подстроку.

### 8. `IsLose` использует `==` вместо `>=`

```go
func (g *Game) IsLose() bool {
    return g.Mistakes == maxMistakes
}
```

Сейчас `Mistakes` растёт по одному и проверяется каждый ход, поэтому `==` срабатывает. `>=` надёжнее: если счётчик когда-нибудь вырастет больше чем на один за ход, проигрыш всё равно зафиксируется.

### 9. `ClearTerminal` запускает процесс на каждый кадр

```go
cmd = exec.Command("cmd", "/c", "cls")  // или "clear"
cmd.Run()
```

Экран чистится запуском внешнего процесса, и так на каждой итерации цикла. Работает, но запускать подпроцесс каждый ход накладно. Тот же результат даёт печать ANSI-последовательности (`\033[H\033[2J`) (задротский вариант), без `cmd` и `clear`.

### 10. Нейминг `STAGES`

```go
var STAGES = [7]string{ ... }
```

В Go нет SCREAMING_CASE, имена пишут в MixedCaps. Для пакетной переменной подойдёт `stages`, с маленькой буквы, раз она не экспортируется.

## АРХИТЕКТУРА

Скелет правильный: есть тип `Game`, файлы разделены, логика отделена от ввода-вывода.

Что можно подтянуть внутри него:

- Свести состояние к одному источнику. Сейчас `Guessed` и `UsedLetter` дублируют друг друга (п. 5), хватит одного множества введённых букв.
- Убрать ввод-вывод из логики. `PlayGame` сейчас и читает ввод, и печатает, и крутит игровой цикл. Чтение буквы стоит вынести в отдельную функцию, а `Game` оставить без `fmt`.
- `Game.Guess` принимает `string`, хотя буква это `rune`, и `UsedLetter` уже на рунах.

Это не переделка, а доводка хорошей основы.

## Итог

Структура сильная: тип `Game`, файлы по смыслу, проверка кириллицы, блокировка повтора букв, показ использованных букв и финального состояния. Починить в первую очередь надо имя файла: `Words.txt` против `words.txt`, иначе на Linux и macOS игра не стартует. Дальше по мелочи: не мешать `fmt.Scan` с `bufio`, поправить выход по любому вводу в меню, свести дублирование состояния. В целом сделано хорошо, правки в основном косметические.
