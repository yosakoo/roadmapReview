# Ревью Hangman

Проект: https://github.com/romalxr/hangmango2

Реализация в процедурном стиле, весь код в одном файле `main.go`, пакет `main`. Игра запускается и работает. Критических багов в логике нет, но есть несколько скрытых проблем и место для доработки архитектуры.

## ХОРОШО

- Слова читаются из файла `words.txt`. Это правильно: при проигрыше неочевидно, какое слово выпадет следующим.
- **Повтор буквы заблокирован для всех букв**, и правильных, и неправильных. `usedLetters` копит все введённые символы, `readLetter` не выпускает повтор. Это главная ошибка большинства реализаций hangman, и здесь её нет.
- `rand.Intn(len(lines))`: корректный диапазон, нет частого off-by-one с `len-1`.
- Ошибка чтения файла завершает программу через `os.Exit(1)`, а не продолжает работу с пустыми данными.
- Перезапуск сделан через цикл в `main` с меню, а не рекурсивным вызовом. Стек не растёт.
- Рунная обработка строк (`[]rune`) подходит для кириллицы.
- Пустой ввод и ввод не-буквы обрабатываются, сообщения понятные.
- `updateGuess` сохраняет исходный регистр буквы (`result[i] = ch`), поэтому слова с заглавной буквой ("Котики") в итоге сходятся с маской и проверка `guess == word` срабатывает.

## ЗАМЕЧАНИЯ

### 1. Несколько `bufio.Reader` на одном `os.Stdin`, теряется ввод

`readInput` и `readLetter` создают **новый** `bufio.NewReader(os.Stdin)` при каждом вызове:

```go
func readInput() string {
    reader := bufio.NewReader(os.Stdin)   // новый ридер каждый вызов
    input, _ := reader.ReadString('\n')
    return strings.TrimSpace(input)
}

func readLetter(usedLetters string) rune {
    for {
        reader := bufio.NewReader(os.Stdin)   // и здесь тоже
        input, _ := reader.ReadString('\n')
        // ...
```

`bufio.Reader` буферизует данные. Если в stdin окажется больше одной строки за раз (например, при вставке текста), `ReadString` прочитает первую строку, а остаток осядет во внутреннем буфере. На следующем ходу создаётся новый ридер, и этот буфер вместе с непрочитанными строками теряется.

Заведите один ридер на всю программу и передавайте его в функции либо держите на уровне пакета:

```go
var reader = bufio.NewReader(os.Stdin)
```

### 2. Игнорируется ошибка чтения ввода

```go
input, _ := reader.ReadString('\n')
```

Ошибка отбрасывается через `_`. На `io.EOF` (например, `Ctrl+D` / `Ctrl+Z` или ввод из закрытого пайпа) `ReadString` вернёт пустую строку и ошибку. Сейчас в `readLetter` это даст бесконечный цикл "Вы ничего не ввели", а в `readInput` бесконечный повтор меню. Ошибку надо проверять и при EOF аккуратно завершать игру.

### 3. Из ввода берётся только первый символ, остальное молча отбрасывается

```go
letter = unicode.ToLower([]rune(input)[0])
```

Если ввести `аб`, программа молча возьмёт `а`, а `б` проигнорирует, без всякого сообщения. Проверки "ровно один символ" нет. Лучше явно сказать, что ожидается одна буква:

```go
runes := []rune(input)
if len(runes) != 1 {
    fmt.Println("\nВведите ровно одну букву")
    continue
}
letter = unicode.ToLower(runes[0])
```

### 4. Принимается латиница, хотя слова только на кириллице

```go
if !unicode.IsLetter(letter) {
    fmt.Println("\nВы ввели не букву: " + string(letter))
}
```

`unicode.IsLetter` пропускает любую букву любого алфавита, в том числе латиницу. А все слова в `words.txt` кириллические. Английскую букву валидация принимает, но в слове она встретиться не может, и игрок впустую сжигает попытку на заведомо невозможной букве.

Раз алфавит слов кириллический, ввод стоит ограничить кириллицей:

```go
func isCyrillic(r rune) bool {
    return r >= 'а' && r <= 'я' || r == 'ё'
}
// ...
if !isCyrillic(letter) {
    fmt.Println("\nОжидается русская буква: " + string(letter))
    continue
}
```

Буквы уже приведены к нижнему регистру через `unicode.ToLower`, поэтому хватает проверки нижнего диапазона.

### 5. Хрупкость при пустой строке в файле

```go
lines := strings.Split(string(data), "\n")
index := rand.Intn(len(lines))
return strings.TrimSpace(lines[index])
```

Сейчас `words.txt` не заканчивается переводом строки, и всё работает. Но если файл отредактировать и оставить пустую строку в конце (а так делают почти все редакторы), `strings.Split` вернёт элемент `""`. Если он выпадет, `word == ""`, маска `guess` тоже пустая, и первая же проверка `guess == word` (`"" == ""`) даёт мгновенную победу с пустым словом.

Пустые строки надо отфильтровать при загрузке:

```go
var words []string
for _, line := range strings.Split(string(data), "\n") {
    if w := strings.TrimSpace(line); w != "" {
        words = append(words, w)
    }
}
```

### 6. Файл перечитывается с диска на каждую игру

`getWordFromFile` читает `words.txt` при каждом старте игры. Список слов статичен, его достаточно загрузить один раз при запуске и передавать в `startGame`. Сейчас на каждое "1: Начать новую игру" идёт лишний поход на диск и парсинг всего файла.

### 7. Картинка висельника пересоздаётся на каждый ход

```go
func printHangman(missCnt int) {
    picture := []string{        // слайс создаётся заново при каждом вызове
        "┌───┐",
        // ...
    }
```

Это статические данные, стадии рисунка не меняются. Слайс стоит вынести на уровень пакета, чтобы не аллоцировать его на каждый ход:

```go
var hangmanPicture = []string{
    "┌───┐",
    // ...
}
```

### 8. Магическое число `2` и нейминг

```go
for i := 0; i < 2+missCnt && i < len(picture); i++ {
```

Число `2` ("всегда показывать первые две строки виселицы") по коду неочевидно. Вынесите в именованную константу.

`maxErr := 6` объявлен как локальная переменная, хотя это константа: `const maxErr = 6` на уровне пакета.

Имя `guess` путает: переменная хранит маску (`_____`), а не догадку игрока. Понятнее `masked` или `progress`. Так же `missCnt` лучше переименовать в `wrongCount`.

### 9. При проигрыше не видно маску слова

```go
if guess == word {
    fmt.Println("\nВы выйграли!")
} else {
    fmt.Println("\nВас повесили!")
}
fmt.Println("Правильное слово " + word)
```

В момент поражения игрок видит полного висельника и сразу правильное слово, но не видит, сколько букв успел открыть. Мелочь, но финальное состояние маски обычно показывают.

### 10. Опечатка и пунктуация

- "Вы вы**й**грали!" нужно "Вы вы**и**грали!".
- В `fmt.Println("Правильное слово " + word)` не хватает двоеточия: "Правильное слово**:** ...".

## АРХИТЕКТУРА

Весь код живёт в функциях пакета `main`, а состояние игры размазано по локальным переменным внутри `startGame`:

```go
word := getWordFromFile()
guess := strings.Repeat("_", len([]rune(word)))
usedLetters := ""
missCnt := 0
maxErr := 6
```

Это процедурный стиль. Напрашивается тип `Game`, который держит состояние и поведение в одном месте.

**`Game`**, состояние игры:
- секретное слово и маска
- счётчик ошибок
- множество введённых букв (`map[rune]bool` вместо строки `usedLetters`: поиск за O(1) и чище, чем `strings.ContainsRune`)
- методы: `GuessLetter`, `IsWon`, `IsLost`, `MaskString`, `UsedLetters`

**`Gallows`**, стадии рисунка:
- метод `Stage(n int) string`

Тогда `startGame` станет чистым игровым циклом, без перемешивания ввода-вывода, проверки букв и логики конца игры в одном месте.

## Итог

Из трёх частых граблей hangman (повтор неправильной буквы, off-by-one в выборе слова, рекурсивный рестарт) здесь нет ни одной. Реализация аккуратнее обычного. Что стоит исправить в первую очередь: единый `bufio.Reader` вместо нового на каждый ввод, проверка "ровно одна буква", ограничение ввода кириллицей, фильтрация пустых строк из файла и обработка ошибки/EOF при чтении. Дальше можно вынести статику на уровень пакета и подумать над типом `Game`. Базово игра работает хорошо, доработки косметические и архитектурные.
